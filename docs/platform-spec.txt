請幫我建立一個基於 HTML / CSS / JavaScript (或 React，視專案技術棧而定，建議使用 Vite + Vanilla JS 或 React 保持輕量) 的現代網頁遊戲平台前端架構。

這個平台的終極目標是支援「未來多人連線（透過伺服器）」與「模組化擴充遊戲（Plug-and-play）」。目前第一階段先實現「單機共用裝置輪流玩 (Pass-and-Play)」，但底層架構必須為未來的聯網與伺服器同步做好準備，不可寫死。

---

### 1. 核心架構與設計要求

1. **架構分離 (Decoupled Architecture)**：
   - **Platform Core (平台核心)**：負責首頁、Tab 切換、導航列、未來的使用者系統 (Account Management)、以及動態載入遊戲的路由器/載入器 (Game Loader)。
   - **Game Plugin Interface (遊戲介面規範)**：定義一個標準的遊戲介面（例如 `BaseGame` 或統一的資料結構），讓未來新增遊戲時，只需要符合該規範並丟入遊戲資料夾，平台就能自動註冊與載入，主平台程式碼不需要大幅修改。
   - **Session / State Management (狀態管理)**：遊戲的進行必須透過抽象的狀態與動作 (Actions/Events)。目前雖是本機輪流玩，但資料結構必須模擬成「由玩家發送 Action，狀態更新」的模式，以便未來無縫對接 WebSocket 伺服器。

2. **UI / UX 風格要求**：
   - 風格：吸引人、現代、簡潔、高質感（可參考現代遊戲啟動器或高質感 SaaS 儀表板，建議深色模式、流暢的轉場動畫、卡片式佈局）。
   - 響應式設計：雖然主要在電腦或平板玩，但排版需保持乾淨俐落。

---

### 2. 頁面與導航結構 (Tabs)

首頁需要有一個乾淨的側邊欄或頂部導航 Tab 系統，目前包含以下頁面/Tab：
1. **Games (遊戲大廳)**：
   - 顯示可選擇的遊戲清單（以精美的卡片呈現）。
   - 點擊遊戲卡片後，會透過 Game Loader 進入該遊戲的專屬大畫面開始遊玩。
   - 遊戲內需要有「返回大廳」的按鈕。
2. **Account (帳號管理 - Placeholder)**：
   - 目前先放一個簡單的預留頁面（顯示「登入/註冊功能開發中，目前為訪客模式」），未來這裡會擴充真正的登入與個人化設定。
3. **Settings (設定 - Placeholder)**：
   - 預留未來聲音、音效、主題等設定頁面。

### 3. 遊戲區塊與 Placeholder

- 目前大廳請提供 **2-3 個遊戲的 Placeholder 卡片**（例如：「Tic-Tac-Toe (圈圈叉叉 - 範例遊戲)」、「Secret Game A (開發中)」、「Secret Game B (敬請期待)」）。
- 點進去「Tic-Tac-Toe」時，可以實作一個極簡的雙人輪流玩 (Pass-and-play) 版本，用來示範「如何實作遊戲內的狀態與輪流機制」。
- 點進其他 Placeholder 則顯示「遊戲開發中，即將登場」。
